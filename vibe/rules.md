# Правила прототипа (plan-3)

Это собственные упрощённые правила AgainstRobot. Тексты, герои и механизмы
сценария созданы для проекта. Полные правила D&D не используются.

## Герои и проверки

| Герой | Здоровье | Сила | Ловкость | Чутьё | Защита | Атака | Урон |
|---|---:|---:|---:|---:|---:|---:|---:|
| Страж | 12 | +3 | +1 | +2 | 12 | +3 | 3 |
| Следопыт | 10 | +1 | +3 | +2 | 11 | +2 | 2 |

Имя после удаления пробелов по краям не может быть пустым. Аватар — лис или
луна. В начале у героя по одному фонарю и бинту; автоматического эффекта у
предметов пока нет. Характеристики — готовые бонусы, без отдельной формулы.

Проверка: целое значение d20 от 1 до 20 + бонус выбранной характеристики.
Успех, если сумма **не меньше** порога; у замка порог 12. Автоматических
критических успехов/провалов нет. Порог модели 1…30, бонусы 0…5.
Запрос с устойчивым ID принадлежит текущей сцене; выполнить его можно один раз.
Результат хранит запрос, грань и проверенный бонус; сумма/успех вычисляются.
Пример: Следопыт, грань 9, ловкость +3 → 12, успех. Страж с той же гранью → 10,
неудача. Неудача у двери ведёт по длинной тропе, а не обрывает историю.

В чате сейчас **фиксированная грань 14**, проверяемая тем же правилом. Текст
ответа заранее задан. Случайные кубики, атаки и автоматическая смена ходов —
plan-7; наличие моделей боя не означает, что игровой бой уже работает.

## Здоровье, бой и предметы

Здоровье всегда 0…максимум. Операция изменения здоровья ограничивает результат
этим диапазоном, включая предельные значения Int; 0 завершает сессию поражением.
Модель допускает максимум 1…100, защиту 1…30, бонус атаки 0…5, урон 1…20.

Минимальное правило будущего боя: d20 + бонус атаки ≥ защита цели означает
попадание и фиксированный урон; промах не меняет здоровье. Герой ходит первым,
затем Медный клещ, затем Сигнальный страж; порядок повторяется. В один ход —
одна атака по живой цели. Эта формула и очередность документированы для plan-7;
plan-3 хранит порядок и текущий индекс, но не исполняет атаки/ходы.

| Враг | Здоровье | Защита | Атака | Урон |
|---|---:|---:|---:|---:|
| Медный клещ | 4 | 10 | +1 | 2 |
| Сигнальный страж | 6 | 12 | +2 | 3 |

Контролируемая операция урона врагу нужна для сценарных данных и проверки
границ; это не автоматическая атака. Завершить бой можно лишь при здоровье 0
у всех врагов. Завершение возвращает фазу игры; победа сессии оформляется
отдельно в сцене финала при живом герое.

Инвентарь содержит только ID предметов каталога и положительные количества.
Добавление/удаление принимает положительное количество; неизвестный предмет,
переполнение, повтор стека и удаление сверх остатка отвергаются. Нулевой
остаток удаляет стек. Повествование не обладает правом менять эти данные.

## Авторитетное состояние и переходы

`Packages/AdventureCore` — локальный пакет Foundation без сторонних зависимостей.
`GameState` — единственная граница доверия для полного Codable-снимка. Вложенные
Codable-модели — значения; отдельно декодированная вложенная модель ещё не
является проверенным игровым состоянием. Идентификаторы — типизированные UUID,
сериализуемые строками. У каталога сценария постоянные ID, у героя и новых
сообщений/запросов/результатов — новые ID; проекции интерфейса их не меняют.

`apply` работает на копии, проверяет результат и лишь затем заменяет состояние.
При ошибке исходное состояние полностью сохраняется. `narrate` добавляет
непустое сообщение с уникальным ID, но не разбирает его как команду.

| Из фазы | Операция | В фазу / условие |
|---|---|---|
| Выбор завязки | begin | Игра |
| Игра | move | Игра, известная сцена |
| Игра | requestCheck | Ожидание броска, текущая сцена и допустимый порог |
| Ожидание броска | resolveCheck | Игра, совпавший запрос и грань 1…20 |
| Игра | startCombat | Бой, текущая сцена боя и непустой набор врагов |
| Бой | finishCombat | Игра, все враги побеждены |
| Игра | complete | Завершение с победой, сцена финала |
| Игра / Бой | changeHealth до 0 | Завершение с поражением |

Здоровье/инвентарь меняются в игре или бою; урон врагам — только в бою.
Новые сообщения допустимы в игре, ожидании броска и бою. Прочие переходы
отвергаются. Завершённая сессия неизменяема. Переходы между известными сценами
не проверяют квестовые условия: пока это операции сценария, а не движок заданий.

Декодирование `GameState` проверяет числовые границы, каталоги, уникальность ID,
ссылки сцен и предметов, результаты бросков и бонусы, соответствие фаз ожидающему
запросу/бою/исходу, определения врагов и порядок боя. Повреждённый снимок
отвергается; версия/хранилище/миграции появятся в plan-4.

## Сценарий на 15 минут и пример состояния

«Маяк в тумане»: 0–3 мин — разговор с рыбачкой Веей в порту; 3–6 мин —
закрытая дверь и проверка ловкости 12 (или длинная тропа); 6–12 мин — двор,
Медный клещ и Сигнальный страж; 12–15 мин — вернуть линзу и зажечь маяк.
Второй локальный вариант — «Тайна лесной станции»: механик, дверь, те же два
механизма, возвращение журнала. Это сценарный материал и тестовые данные;
чат пока демонстрирует только действие и проверку.

Полный проверяемый пример создаётся так:

```swift
var state = try AdventureFixtures.newSession(name: "Мира", kind: .scout)
// selectingPremise; здоровье 10/10; фонарь ×1, бинт ×1;
// conversation-сцена 00000000-0000-0000-0000-000000000010.
try state.apply(.begin)
let request = CheckRequest(sceneID: state.sceneID, ability: .agility, difficulty: 12)
try state.apply(.requestCheck(request))
// awaitingRoll, pendingCheck содержит request, combat и outcome отсутствуют.
let data = try JSONEncoder().encode(state)
let restored = try JSONDecoder().decode(GameState.self, from: data)
// restored == state; request.id, hero.id и все ID каталога сохранены.
```

`FixtureTests.testScriptedScenarioTraversesConversationCheckTwoEnemyBattleAndEnding`
проходит весь сценарий контролируемыми операциями без случайности и UI.
`MockAdventureSession` хранит черновики создания, пожелание и режим просмотра;
после принятия завязки сообщения, ожидание броска, здоровье и инвентарь читает
из `GameState`. На главной по-прежнему только пример истории; диск и сеть не
используются.
