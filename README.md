# AgainstRobot

Прототип одиночного приключения для iPhone на SwiftUI. В локальном режиме
доступен путь: новая игра → готовый герой, имя и аватар → завязка → чат
с тестовым броском → карточка героя → главная и продолжение в памяти.
Завязки, ответы и результат броска заранее заданы. ИИ, правила, сохранения,
голос и карта появятся в следующих планах. История на главной содержит
явно отмеченный пример; закрытие приложения сбрасывает текущую игру.

**Каркас и CI проверены:** Debug/Release и 2 UI-теста прошли
на [облачном Mac](https://github.com/antipin-aleksei/AgainstRobot/actions/runs/40526374430). Реализация plan-2 проходит проверку и отдельное ревью.

## Требования

- Выбранная базовая среда: **Xcode 16.0**, macOS **14.5+**, SDK iOS **18.0**.
  Можно использовать более новый совместимый Xcode с его требованиями к macOS.
- Deployment target: **iOS 17.0**, только iPhone. Swift — языковой режим **5.0**
  компилятора из Xcode 16 (код использует Swift 5.9 switch expressions).
- Для указанных UI-тестов: симулятор **iPhone 16 / iOS 18.0**. Другой установленный
  iPhone-симулятор с iOS 17+ можно выбрать через `-destination`.
- Зависимостей приложения, менеджера пакетов и генератора проекта нет.
  `.xcodeproj` и общая схема `AgainstRobot` хранятся в Git.

Это выбранные требования, а не зафиксированная успешная среда сборки. В среде
подготовки доступны Linux x86_64 и Python 3.12.14; Swift и Xcode отсутствуют.

## Открытие и запуск на Mac

1. Открыть `AgainstRobot.xcodeproj` в Xcode и выбрать схему `AgainstRobot`.
2. Установить iOS Simulator runtime в Xcode Settings → Components, если нужен.
3. Выбрать iPhone-симулятор и выполнить Product → Run (`⌘R`).
4. На главной `AgainstRobot` нажать «Новая игра», выбрать героя и аватар,
   ввести имя, принять завязку и отправить действие. Выполнить тестовый бросок,
   открыть карточку героя, вернуться на главную и продолжить игру.
5. Проверить пример истории и переключить «Тестовые данные» в обе стороны.
   При выключении вход в игру недоступен: сервис пока не подключён.

Для симулятора аккаунт разработчика не требуется. Для физического iPhone
назначить собственный Team и уникальный Bundle Identifier в Signing &
Capabilities. В проекте нет привязки к аккаунту или сертификатам.

## Команды проверки на Mac

Из корня репозитория проверить фактические версии и доступные устройства:

```sh
xcodebuild -version
xcrun swift --version
xcrun simctl list devices available
```

Собрать Debug для симулятора без подписи:

```sh
xcodebuild -project AgainstRobot.xcodeproj \
  -scheme AgainstRobot -configuration Debug -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO build
```

Запустить UI-тесты (полный путь, история, возвраты и переключение
mock-режима). Если такого симулятора нет, заменить `-destination` на устройство
из списка выше, например `platform=iOS Simulator,id=<UDID>`:

```sh
xcodebuild -project AgainstRobot.xcodeproj \
  -scheme AgainstRobot -configuration Debug \
  -destination 'platform=iOS Simulator,name=iPhone 16,OS=18.0' \
  -derivedDataPath build/DerivedData \
  -resultBundlePath build/SmokeTests.xcresult CODE_SIGNING_ALLOWED=NO test
```

При повторном тестировании использовать новый путь `-resultBundlePath`, если
папка результата уже существует. Локально в среде подготовки UI-тесты не выполняются:
в Linux `xcodebuild` заканчивается кодом 127 (`command not found`). Это не
результат RED или GREEN для поведения приложения. Результаты облачной сборки, запуска,
версии Xcode и destination записаны в [plan-1](vibe/plans/plan-1.md),
сведения об успешном CI — ниже.

## CI на облачном Mac

Workflow [.github/workflows/ios-ci.yml](.github/workflows/ios-ci.yml) запускается
при push в `main`, для pull request и вручную через GitHub Actions → **iOS CI** →
**Run workflow**. Задание выполняется **только в публичном репозитории**:
`github.event.repository.private == false`; в приватном оно пропускается.
Используется стандартный hosted runner `macos-15-intel`, без larger runner и секретов.
Публикация репозитория и первый реальный запуск — отдельные действия; наличие
workflow не подтверждает, что они выполнены.

CI явно выбирает Xcode **16.4**, записывает версии инструментов и выбирает
доступный iPhone-симулятор с runtime того же основного поколения, что и SDK
(iOS 18 для выбранного Xcode). Затем ожидает загрузку симулятора, выполняет
Debug `build-for-testing`, поведенческие UI-тесты через
`test-without-building` и Release `build`, везде без подписи. Проверка
`xcresulttool get test-results summary` требует хотя бы одного завершённого
успешного теста и нуля ошибок; пустой прогон не считается успешным.

Ограничение задания — 30 минут; устаревший запуск той же ветки/PR отменяется.
Логи, версии, destination, JSON результата и `.xcresult` сохраняются в артефакте
`ios-diagnostics-<run_id>-<attempt>` на 7 дней, в том числе при ошибке, если файлы
успели появиться. Внешние actions закреплены полными SHA, токен имеет только
`contents: read`, credentials после checkout не сохраняются.

**[Успешный прогон](https://github.com/antipin-aleksei/AgainstRobot/actions/runs/40526374430)** на SHA `72464f27732462acb32d86cb7c034447df7d1755`:
Debug и Release собраны; **2 UI-теста прошли, 0 ошибок**. Xcode 16.4, macOS 15.7.9,
iPhone 16 / iOS 18.6. Исправлен тест, нажимавший на обёртку строки вместо
вложенного переключателя; все проверки сохранены.

Результаты, первый неудачный запуск и ограничения записаны
в [plan-11](vibe/plans/plan-11.md); [plan-1](vibe/plans/plan-1.md) выполнен.
CI подтверждает автоматический запуск на симуляторе, не ручную оценку интерфейса
или работу на физическом iPhone.

## Режим данных и структура

`AppConfiguration.usesMockData` включён по умолчанию. Переключатель на главной
меняет только состояние в памяти; перезапуск возвращает безопасное значение.
Включённый режим открывает локальный пример приключения. При
выключении отображается «Сервис не подключён». Оба режима сейчас полностью
офлайн: сетевого клиента, URL, ключей и платных вызовов нет. Подключение сервиса
вынесено в последующие планы.

- `AgainstRobot/App` — точка входа и состояние конфигурации.
- `AgainstRobot/Features` — главная, создание героя, завязка, чат и модальная карточка.
- `AgainstRobot/Models` — маршруты и `MockAdventureSession`; правила и авторитетное состояние — plan-3.
- `AgainstRobot/Services` — конфигурация; реальных сервисов пока нет.
- `AgainstRobotUITests` — проверки полного пути, возвратов, ввода и офлайн-режима; скриншоты в xcresult.

Планы: [vibe/README.md](vibe/README.md). Рабочий процесс:
[vibe/SUPERPOWERS.md](vibe/SUPERPOWERS.md).

## Тестовый интерфейс (plan-2)

`MockAdventureSession` хранит выбор героя, имя, аватар, пожелание и сообщения
только в памяти. Пустое имя и пустое действие отправить нельзя; пробелы по
краям имени убираются при отображении героя. «Другой пример завязки» меняет
один из двух готовых текстов с коротким индикатором подготовки. Пожелание
показывается в описании, но не обрабатывается ИИ. После отправки действия
пример запрашивает бросок с фиксированным результатом 14 — это демонстрация
интерфейса, а не случайный бросок или реализация правил.

Системные шрифты поддерживают Dynamic Type, длинные тексты переносятся и
прокручиваются. Основные кнопки закреплены у нижнего края; Return закрывает
клавиатуру, отправка действия выполняется отдельной кнопкой. Сохранения,
фотографии и голос честно обозначены как недоступные. Новая игра заменяет
текущий пример в памяти. Образец истории открывается в отдельной сессии
и сохраняет текущего героя, сообщения и незавершённый бросок. Принятие завязки
завершает создание героя: из чата нельзя случайно вернуться и начать его заново.

CI экспортирует вложения UI-тестов командой
`xcrun xcresulttool export attachments --path build/ci/SmokeTests.xcresult --output-path build/ci/attachments`.
PNG и исходный xcresult доступны в диагностическом артефакте на странице запуска.
